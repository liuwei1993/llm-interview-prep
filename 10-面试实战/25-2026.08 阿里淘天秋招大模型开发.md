### **2026.08 阿里淘天秋招大模型开发**

今天这一期内容，是26年8月秋招阿里淘天校招一面的内容。一面内容，基本上是围绕项目展开提问的。只有一个问题，MCP 相关的技术，只面试官主动提问的。

从这个角度来看，从八股，知识的角度上来分析，好像借鉴意义不大了。

不过换一个角度来思考：

因为本次面试大部分内容是围绕项目，简历来展开的。通过这个内容我们可以学习到**面试官通常对简历是怎么提问题，喜欢怎么问，学会了这个，我们用这个方法论，可以在面试前提早预测面试重点，做好准备**。

毫不夸张地说，学会了这个技巧，如果你做了好准备，面试前70的内容都是你准备过的题目，那么面试不就是十拿九稳了？

讲解知识之前，我们先说一下这个同学的背景：这个同学实习经历，本身的技术栈是和后端相关的，有比较丰富的后端实习经历，所以他的秋招一方面是投递： 后端 + AI的岗位，一方面是投递：纯AI(AI开发的岗位)。

**本次面试的岗位，是纯AI的岗位。**（我写这个是给后面分析面试官为什么会问一些后端的内容，来做一些铺垫）。

同时，对于问题的解析，有一些问题其实是可以复用到笔记里已有的项目的，所以对于这些问题的解析，我会按照我们笔记里的项目，来组织答案。

有一些问题是和这个同学个人背景（后端项目） 相关的，提问就围绕了后端内容 + 传统技术，那么这一块内容我会不解析答案，只是带大家分析面试官为什么会这么问。

###### 相比这些工具，你的项目优势主要在哪里？

 **💡 思路：**

这个问题的背景就是这个同学做了双路检索（RAG）来处理代码仓库。因此面试官问了8.3, 8.4, 8.5 三个问题。我把这三个问题，总结成了一个：**你有没有对比过claudecode，codex功能的检索模块，他们是怎么实现的，对比他们你的双路检索有什么优势吗？**

这里的回答思路，可以参考我们笔记[RAG趋势探讨](https://my.feishu.cn/docx/GikId1snboM6LyxxGPXc0kDdnub#doxcnuSMVhE1VDaDOutYSAYC8sb)的章节，第一个角度是虽然主流的coding 框架都放弃了RAG, 不代表用RAG的方案就不好，他仍然有他的优势。 

如果还能够结合当前项目的特点，比如对RAG做了相应适配（比如我们forgepilot仓库，代码仓库大小超过300GB，主流coding agent都不能用） + 做了实验对比，说明效果更好，这个答案就更加丰满和有说服力。

但是我不太知道这个同学的具体业务场景，所以咱们就只从第一个叫角度来回答一下。（因为缺少具体业务场景，下面这个回答我觉得有点单薄，我们就当借助这个问题，复习RAG是否被取代了的这个知识点吧）

📝 参考回答

Claude Code 和 Codex 的基础代码检索都可以概括为** Agentic Search + grep/ripgrep**：模型自己决定搜什么，读取命中的代码，再根据新线索继续搜索。Claude Code 主要通过专用搜索工具调用，Codex 的公开本地实现则通过命令执行工具运行 rg。这种方式灵活，能直接查看工作区的最新代码，很适合跨文件探索和问题排查。

我们采用 **关键词 + 向量双路检索，并不是认为这种方式不好，而是做了不同的取舍**：关键词检索匹配函数名、配置项等明确线索，向量检索补充自然语言描述与代码之间的 语义匹配，再把融合、筛选后的相关片段交给模型。

**我们看重的是在线延迟和 Token预算的可控性。**通过预建索引，尽量在一次检索中找齐证据，减少模型反复“决定搜什么—调用工具—读取结果”的往返，也减少中间内容进入上下文。我们的代码相对来说比较稳定，修改不会特别频繁，更多的情况是基于代码仓库，进行理解和分析，这样在代码变动后，进行分块，向量维护的开销的成本会降低，在多轮对话中，检索速度更快，也会更省Token的好处会更明显。
