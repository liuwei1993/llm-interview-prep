# 方向九 · 大模型基础、推理部署与 LLM 应用工程

> 覆盖：大模型推理与部署优化（KV Cache / PagedAttention / 连续批处理 / 量化）、MoE 与稀疏激活、微调与对齐选型（LoRA/QLoRA/SFT vs DPO/RLHF）、微调 vs RAG vs Prompt、模型蒸馏与小模型化、RLHF/DPO 与对齐数据构造、LLM 应用缓存分层（Prompt Cache / KV Cache 复用）、语义缓存、模型路由与级联、Prompt 自动优化与 DSPy、成本核算与 Token 预算、Test-time Compute、长上下文与位置编码外推（RoPE Scaling / YaRN）。

## Q1. 大模型推理与部署优化有哪些手段？
**答题要点**
- **KV Cache**：缓存已算过的注意力 K/V，避免每生成一个 token 重算全序列 → 省算力。
- **PagedAttention**：把 KV Cache 分页管理（像操作系统虚拟内存），减少碎片、提升显存利用率 → vLLM 的核心。
- **连续批处理（Continuous Batching）**：请求随到随处理、动态拼批，而不是等一批凑齐 → 吞吐大增。
- **量化**：INT8/INT4/FP8 降低显存与带宽需求，换速度；精度有损。
- **其他**：投机解码、FlashAttention、张量并行/流水并行、prefix caching。
**加分点**
- 提「**吞吐 vs 延迟**」的权衡：批处理提升吞吐但可能增延迟。
- 提「**首 token 延迟（TTFT）vs 每 token 延迟（TPOT）**」是两个不同指标。
- 提「**显存是瓶颈**：KV Cache 随并发与序列长度线性增长」。

## Q2. 什么是 MoE（混合专家）与稀疏激活？
**答题要点**
- 模型由多个"专家"子网络 + 一个**路由（gate）**组成，每个 token 只激活**少数专家**（稀疏），而非全部参数。
- 好处：**总参数量大（容量大）但每 token 计算量小** → 同等算力下模型更强。
- 挑战：**显存占用大**（要装下所有专家）、**负载不均**（某些专家过载）、**路由训练难**、通信开销（专家分布在不同设备）。
**加分点**
- 提「**稀疏 ≠ 便宜**：训练和部署的工程复杂度更高」。
- 提「代表模型：Mixtral、DeepSeek 系列等」。
- 提「**推理时只看激活参数**，但显存要看总参数」。

## Q3. 微调与对齐怎么选型？（LoRA/QLoRA、SFT vs DPO/RLHF）
**答题要点**
- **PEFT（参数高效微调）**：
  - **LoRA**：冻结原权重，只训练低秩旁路矩阵 → 显存小、可插拔、可多任务共存。
  - **QLoRA**：基座量化到 4bit 再训 LoRA → 单卡也能微调大模型。
- **对齐阶段**：
  - **SFT（监督微调）**：教格式与任务，是基础。
  - **RLHF / DPO**：对齐人类偏好。**DPO 直接用偏好对训练，比 RLHF 简单稳定**（不需奖励模型+PPO），是当前主流。
- 顺序通常是：预训练 → SFT →（可选）DPO/RLHF。
**加分点**
- 提「**微调数据质量 >> 数量**」，几百条高质量 > 几万条噪声。
- 提「**微调容易灾难性遗忘**（忘掉通用能力）」，可用 LoRA/混合通用数据缓解。
- 提「**对齐的成本与不稳定**（RLHF 调参难），DPO 更实用」。

## Q4. 微调 vs RAG vs Prompt，怎么选？
**答题要点**
- **Prompt**：先试。适合**任务明确、知识已在模型里**、快速验证，成本最低。
- **RAG**：适合**知识频繁更新、需要引用来溯源、知识量大**（外挂知识库），不动模型。
- **微调**：适合**风格/格式/领域术语/固定任务**的稳定对齐，或需要压缩进小模型。
- 实战常用**组合**：微调定格式与能力 + RAG 供实时知识。
**加分点**
- 决策三问：知识会不会变？（变→RAG）需要溯源吗？（要→RAG）是"怎么做"还是"知道什么"？（怎么做→微调/提示）。
- 提「**微调不能可靠注入新知识**（易幻觉），知识更新优先 RAG」。

## Q5. 模型蒸馏与小模型化怎么做？
**答题要点**
- 用一个强"教师"模型指导小"学生"模型（软标签/分布对齐/中间表示对齐），把能力压缩进小模型。
- 目的：**降本、降延迟、可本地部署、可控**。
- 相关：量化压缩、剪枝、投机解码。
**加分点**
- 提「**蒸馏常配合合成数据**」（教师生成高质量训练数据）。
- 提「**小模型 + 好检索/工具** 在很多任务上可媲美大模型」（小模型是大系统的组件）。
- 提「保留多少能力取决于任务，通用能力会打折」。

## Q6. RLHF / DPO 的数据怎么构造？标注质量怎么保证？
**答题要点**
- 需要**偏好数据**（同一 prompt 的两个回答，标注哪个更好）或**排序数据**。
- 构造：人工标注（准但贵）、模型自我生成 + 人工筛选、**AI 反馈（RLAIF）**。
- 质量保证：**明确标注规范**、多标注者 + **一致性（Kappa）检查**、抽检、难例专门标注。
**加分点**
- 提「**偏好数据有偏**（标注者偏好影响模型行为）」。
- 提「DPO 用偏好对即可，比 RLHF 少一个奖励模型环节」。

## Q7. LLM 应用的缓存分层（Prompt Cache / KV Cache 复用）？
**答题要点**
- **Prompt Cache**：把相同前缀（系统提示、长文档）的 KV 缓存下来，下次请求直接复用 → 降延迟降成本。OpenAI/Anthropic 等已提供，注意**前缀必须完全一致**才能命中。
- **KV Cache 复用**：多轮对话中复用历史部分的 KV（prefix caching）。
- **语义缓存**：把"意思相同"的问题的答案缓存（下一题）。
**加分点**
- 提「**前缀缓存的设计影响 prompt 结构**」——把稳定的内容放前面，变化内容放后面。
- 提「缓存**失效与一致性**」：知识更新后要能失效缓存。

## Q8. 语义缓存怎么做？什么不能缓存？
**答题要点**
- 用 Embedding 比对请求相似度，命中（高于阈值）则直接返回缓存答案，省一次 LLM 调用。
- 适用：**高频、答案稳定**的查询（FAQ、常识）。
- **不能缓存**：有副作用/需要实时数据的操作、个性化答案、时效性强的内容、需要授权校验的查询。
**加分点**
- 提「**阈值调优**：太低误命中（答非所问），太高命中率低」。
- 提「**命名空间 + TTL**」：按用户/租户/时间隔离，防止串号与过期数据。
- 提「**副作用步骤绝不可缓存**」（如扣款、下单）。

## Q9. 模型路由与级联（Model Router / LLM Cascade）？
**答题要点**
- **路由**：按问题难度/类型把请求分给不同模型（简单→小模型，难→大模型），省钱省时。
- **级联**：先小模型试，**置信度低或失败再升级**到大模型，设**升级上限**避免全升级。
- 收益：在保证质量前提下大幅降成本。
**加分点**
- 提「多供应商降级：主模型挂了自动切备用」。
- 提「路由/级联的判据要**可评测**（升级率、误升/漏升）」。
- 提「与语义缓存配合：缓存命中直接返回，未命中才进级联」。

## Q10. Prompt 自动优化与 DSPy 是什么？
**答题要点**
- **DSPy**：把 prompt 当"要编译的程序"——定义模块（signature）与指标，用**评测集驱动自动优化** prompt/示例（few-shot 选择、指令生成），形成编译式闭环。
- 价值：减少手工调 prompt 的试错、结构化可复用、有指标可衡量。
- 代价：**编译成本高**（要跑大量评测）、可能有**过拟合**风险。
**加分点**
- 提「**holdout 集防过拟合**」，编译用的和验证用的要分开。
- 提「适合**指标清晰、数据充足**的场景，不适合一次性任务」。

## Q11. LLM 成本怎么核算？Token 预算怎么管？
**答题要点**
- 成本 = 输入 token + 输出 token（单价不同）乘以调用次数，加上检索/工具/存储等间接成本。
- 管理：**预算上限**（每任务/每会话/每日）、**按步归因**（找出最贵环节）、缓存复用、模型路由、输出压缩（让它少说废话）、控制上下文长度。
**加分点**
- 提「**输出 token 通常比输入贵**，限制输出长度很有效」。
- 提「**长上下文/多轮反思是成本黑洞**」，要设上限。
- 提「用**每解决一个任务的成本**当北极星指标」。

## Q12. Test-time Compute 与推理时扩展是什么？（PRM / Best-of-N / Verifier）
**答题要点**
- 思路：**不重新训练**，而是**在推理时多花算力**换质量。
- 手段：**Best-of-N**（采样 N 个答案再挑最好的）、**Verifier / PRM（过程奖励模型）**（逐步打分/挑最终答案）、**自我一致性**（多数投票）、**思维链/反思延长**。
- 关键：**验证比生成容易**，所以"生成多个+验证挑选"有效。
**加分点**
- 提「**PRM（过程奖励）> ORM（结果奖励）**：对每一步打分比只看结果更能引导推理」。
- 提「成本随 N 线性增长，要按任务价值决定 N」。
- 提「与模型级联/路由结合，只在难题上扩展算力」。

## Q13. 大模型长上下文与位置编码外推（RoPE Scaling / YaRN）
**答题要点**
- 位置信息靠**位置编码**提供，主流是 **RoPE（旋转位置编码）**，它把位置编码成向量的旋转角，天然表达**相对位置**。
- 模型训练时的上下文长度固定（如 8K），想吃到 128K 直接拉长会**外推失效**：超过训练见过的位置范围，注意力打分分布崩掉。
- 两类解法：
  - **位置插值/缩放**：PI、NTK-aware、**YaRN**——把长位置「压回」训练过的范围，通常**免训练或轻量微调**即可扩展；
  - **长上下文微调**：用长文本数据继续训练，让模型真正适应长序列（效果好，需要数据与算力）。
- 工程配套：FlashAttention、分块/稀疏注意力、KV Cache 分页（PagedAttention）来扛显存与计算。
**加分点**
- 能讲清「**RoPE 是相对位置、为什么外推会失效**」，并对比「插值（免训练、效果打折）vs 长上下文微调（效果好、要数据）」。
- 提「**长上下文 ≠ 有效上下文**」：Needle-in-Haystack 通过 ≠ 复杂推理不退化，要分层测（检索能力 / 多跳推理 / 位置鲁棒性）；并有 attention sink 等实证现象。
- 提「**成本硬约束**」：推理成本随长度增长，长上下文与 RAG 是**互补不是替代**（信噪比、成本）。

## Q14. 投机解码（Speculative Decoding）是怎么加速推理的？
**答题要点**
- 背景：LLM 自回归生成是**逐 token 串行**的，每生成一个 token 都要跑一遍大模型前向；而单序列前向是**访存受限（memory-bound）**——显存带宽没被喂饱，算力反而闲着，所以"猜"比"算"更划算。
- 思路：用**便宜的"草稿（draft）"来猜**，再用**目标大模型一次性并行验证**。验证多个候选 token 只需一次前向（可并行打分），比逐个生成便宜得多。
- 流程：① 草稿来源（小模型 / 目标模型加多个预测头 / 特征外推 / n-gram、检索结果）**一次连续生成 K 个候选 token**；② 大模型对这 K+1 个位置**一次前向**给出概率；③ 按接受准则（如 Speculative Sampling 的拒绝采样，保证输出分布与目标模型**完全一致**）逐个接受/拒绝；④ 一旦拒绝，就从该位置按目标分布重采样，继续下一轮。
- 关键性质：**不改变输出分布（lossless）**，只是加速；加速比主要取决于**接受率（acceptance rate）**与草稿成本。
**加分点**
- 能讲清「**为什么无损**」：草稿只决定"猜什么"，最终是否接受由目标模型的概率做拒绝采样校正，理论分布不变。
- 提「**草稿来源的几种做法**」：小 draft model（如 7B 配 70B）、**Medusa 多头**、**EAGLE 特征级外推**、**自投机（self-speculative / layer skip）**、检索或 n-gram 草稿。
- 提「**收益取决于场景**」：低并发、访存受限时收益大；批量很大（转为算力受限）时收益会被摊薄甚至变慢。
- 提「与其他加速手段**叠加**」：连续批处理 + PagedAttention + 量化 + 投机解码可同时用；延迟看 **TPOT（每 token 延迟）**，吞吐看 tokens/s。
## Q15. LLM 的采样与解码参数怎么理解？（Temperature / Top-p / Top-k / 可复现性）
**答题要点**
- 模型每步输出的是**词表上的概率分布**，解码策略决定"从分布里怎么挑下一个 token"。
  - **确定性解码**：贪心（每步取最大概率）、束搜索（Beam Search，保留多条候选）——适合翻译、结构化抽取；但束搜索在开放式生成里易平庸、重复。
  - **随机解码**：Temperature T 把 logits 除以 T 再 softmax（T→0 趋近贪心、T>1 更随机）；Top-k 只在前 k 个候选里采样；Top-p（核采样）取**累积概率达 p 的最小集合**再采样，比固定 Top-k 更自适应；重复惩罚（presence / frequency penalty）压低已出现 token。
- 工程取舍：Agent / 工具调用 / 结构化输出场景用**低温（0~0.3）**保证 JSON 合法、工具名选对；创意写作才调高。
**加分点**
- 提「**Temperature=0 也不保证完全可复现**」：浮点非确定性、batch 组成不同、MoE 路由、GPU kernel 差异都会让同一 prompt 出不同结果——所以评测要**多次采样看方差**，不能只跑一次。
- 提「**约束解码**（Constrained Decoding / grammar、JSON schema）比"靠低温抽卡"更可靠」，以及 **logprob / logit_bias** 可用来做置信度与偏好控制。
- 提「采样参数要当**配置项 + 版本化**管理，改一次就回归评测」，并注意 **Top-p 与 Temperature 的裁剪顺序**（通常是先温度后截断）。

## Q16. Chain-of-Thought 与推理增强提示怎么做？（CoT / Zero-shot CoT / 提示结构）
**答题要点**
- CoT 的核心：让模型**先写推理过程再给答案**，把"一步直出"变成"多步显式推理"，显著提升多步算术、逻辑、常识推理。Few-shot CoT 给带推理步骤的示例；Zero-shot CoT 用一句"让我们一步步思考（Let's think step by step）"触发。
- 为什么有效：Transformer 每层算力固定，显式中间步骤相当于给模型"额外的计算与工作记忆"，把难问题拆成可控的下一步。
- 其它推理增强手段：**自洽性（Self-Consistency）**多次采样投票；**由易到难（Least-to-Most）**；**分解-求解（Decompose-then-Solve）**；**格式约束**（先列已知条件、再列式子、最后给答案）。
- 何时**不该**用 CoT：简单事实问答、分类/抽取、延迟敏感场景——CoT 增加 token 与延迟，还可能"想多了"引入错误；对推理模型（o1/R1 类）也不必手动加"一步步"，它们已内置长推理。
**加分点**
- 提「**CoT 与推理模型的区别**」：手动 CoT 是 prompt 层技巧；推理模型把长思维链**内化到训练与推理时扩展（test-time compute）**里。
- 提「**CoT 的可信度问题**」：模型写出的推理链**未必是它真正决策的依据**（可能是事后合理化），不能盲信解释，要用结果校验。
- 提「**提示结构工程**」：角色 + 任务 + 约束 + 输出格式 + 示例，缺一不可；few-shot 示例要**与目标分布一致、覆盖边界情况**，数量不是越多越好。
- 提「**与工具/RAG 联动**」：CoT 减少跳步，但事实仍要靠检索/工具 grounding，否则只是"流畅地编"。

## Q17. 合成数据与 Self-Instruct 是什么？怎么用它做微调 / 蒸馏数据？
**答题要点**
- 动机：高质量人工标注数据又贵又慢，而微调、对齐、蒸馏都需要**大量、多样、有难度梯度**的数据。
- **Self-Instruct**：用强模型（教师）从少量种子任务/示例出发，**自动生成新指令 + 答案**，过滤后回喂训练学生模型；关键工序是**去重 + 多样性控制 + 质量过滤**。
- 常见合成手段：种子扩写（指令/输入/输出三元组）、**Evol-Instruct**（把简单指令逐步加难：加约束、加推理步、换多语言）、**拒绝采样**（Rejection Sampling，只留模型答对的轨迹做 SFT）、RL/DPO 的偏好数据合成、以及从真实日志"改写 + 扩样"。
- 质量把关：LLM-as-judge 打分 + 规则过滤（格式/长度、MinHash 或 embedding 相似度去重）+ 难度分层；同时保留**人工抽检**与**held-out 真实测试集**。
- 蒸馏数据：教师对同一 prompt 采样多条 → 保留高质量/一致的答案（类似 Self-Consistency 投票），教小模型"过程 + 结果"。
**加分点**
- 提「**模型坍缩（Model Collapse）**」风险：反复用自己/同源模型生成的数据训练，分布会**越训越窄**，长尾与多样性丢失 → 必须掺真实数据、控合成比例、做多样性度量。
- 提「**分布偏见与污染**」：合成数据会继承教师的风格与错误，甚至引入训练集污染，要专门检测 **benchmark 泄漏**。
- 提「**合成 ≠ 免费**」：生成 + 过滤 + 评测都有 token 与工程成本，要算"每单位有效样本成本"。
- 提「**与 RLHF / RLAIF 的关系**」：Self-Instruct 多用于 SFT 冷启动与能力覆盖，RLHF/RLAIF 用于偏好对齐；**RLAIF 就是用模型当偏好标注者**。
