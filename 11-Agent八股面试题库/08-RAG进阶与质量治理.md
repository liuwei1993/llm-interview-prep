# 方向八 · RAG 进阶与质量治理

> 覆盖：RAG 幻觉治理与引用溯源、RAG 评估体系（RAGAS）、长上下文 vs RAG、GraphRAG、多模态 RAG 与文档解析、多跳问答、RAPTOR 层级索引、Contextual Retrieval、Agentic RAG / Self-RAG、跨语言 RAG、Text-to-SQL、查询意图分类与路由。

---

## Q1. RAG 的幻觉怎么治理？引用溯源怎么做（Grounding / Citation）？
**答题要点**
- 幻觉来源：检索没命中相关内容、命中但模型没忠实使用、模型臆造。
- 治理：① **强制基于证据作答**（prompt 要求"只依据给定资料，无依据就说不知道"）；② **引用溯源**（答案带来源片段/文档 ID，可点开核对）；③ **忠实度校验**（用另一模型/规则检查每句是否被证据支撑）；④ 检索质量先修（garbage in garbage out）。
**加分点**
- 提「**带引用是信任的基础**」，且引用要能验证（指向真实存在的片段）。
- 提「拒答（abstention）**是正确行为**，不是失败」——无依据时敢于说不知道。
- 提「**答案级 + 句子级**两种引用粒度」的取舍。

## Q2. RAG 评估体系怎么搭（RAGAS 四指标）？
**答题要点**
- **RAGAS 四核心指标**：
  1. **Faithfulness（忠实度）**：答案是否被检索上下文支撑（查幻觉）。
  2. **Answer Relevancy（答案相关性）**：答案是否切题。
  3. **Context Precision（上下文精确率）**：检索到的相关内容排得靠不靠前。
  4. **Context Recall（上下文召回率）**：该召回的证据有没有召回全。
- 拆开评估**检索**与**生成**两段，定位问题在哪一段。
**加分点**
- 提「**先修检索再修生成**」：召回差则生成再好也白搭。
- 提「LLM-as-judge 实现这些指标，但要与人工抽检校准」。
- 提「建领域专属评测集」比通用指标更能反映业务。

## Q3. 长上下文 vs RAG，怎么取舍？
**答题要点**
- 长上下文（把大量内容直接塞进窗口）优点：无检索损失、无需索引；缺点：**贵**、**Lost in the Middle**（中间内容被忽略）、噪声干扰、无法覆盖超出窗口的语料。
- RAG 优点：可扩展、便宜、可控、可引用；缺点：依赖检索质量，可能漏召回。
- **混合架构**：先用检索缩小范围，再把高相关内容放进长窗口精读。
**加分点**
- 提「窗口大 ≠ 该全塞」，**信噪比**和成本才是决定因素。
- 提「**上下文压缩**」：把长文档压成摘要/关键片段再入窗。
- 提「长上下文适合**单文档深度问答**，RAG 适合**海量知识库**」。

## Q4. GraphRAG 是什么？什么时候值得用？
**答题要点**
- 把语料建成**知识图谱**（实体-关系），检索时结合图结构（社区摘要、多跳遍历），而不是纯向量相似度。
- 擅长：**全局性问题**（"整个语料讲了哪些主题"）、**多跳关系推理**（A 和 C 通过 B 有什么关系）。
- 代价：**建图贵**（抽取实体关系要大量 LLM 调用）、更新难、维护复杂。
**加分点**
- 提「**Hybrid**：局部用向量，全局/多跳用图」。
- 提「适合**小而关键**的语料（如公司知识、科研文献），不适合频繁变更的大语料」。
- 提「与多跳问答是同类问题的不同解法」。

## Q5. 多模态 RAG 与文档解析怎么做？
**答题要点**
- 文档里有图、表、扫描件、公式 → 纯文本抽取会丢信息。
- 手段：**Layout-aware Parsing**（按版面结构解析，保留标题/表格/图注）、**表格结构化提取**、**视觉检索（ColPali 类）**——直接把页面当图用视觉模型编码检索、**图表分块**（图+说明一起）。
- 难点：表格跨页、公式、手写、扫描质量。
**加分点**
- 提「**用视觉模型而非 OCR**」能更好保留版面语义。
- 提「**图与文的联合检索**」：图要能被文字查询命中。
- 提「解析质量直接决定 RAG 上限」。

## Q6. RAG 多跳问答（Multi-hop QA）怎么做？
**答题要点**
- 问题需要**串联多个事实**才能回答（"X 的创始人的母校在哪"）→ 单次检索不够。
- 手段：**问题分解**（拆成子问题逐个检索）、**迭代检索**（用上一跳的结果驱动下一跳查询）、**查询图/推理链**、多跳后**融合答案**。
**加分点**
- 提「**迭代检索 = Agentic RAG 的一种**」。
- 提「防止**误差累积**」：每跳要验证，走错要能回溯。
- 提「**多跳的成本控制**」：不是所有问题都要多跳，先分类。

## Q7. RAPTOR 是什么？长文档与层级索引怎么处理？
**答题要点**
- **RAPTOR**：递归地把文本聚类 + 摘要，建**摘要树**（叶子是原文块，上层是摘要）。检索时可跨层级命中——既查细节也查全局。
- 解决：长文档"只见树木不见森林"的问题。
- 代价：建树要额外 LLM 摘要开销。
**加分点**
- 提「与 GraphRAG 类似目标（全局理解），但实现更轻（聚类+摘要 vs 建图）」。
- 提「适合**长报告/书/法规**这类有层级结构的文档」。

## Q8. Contextual Retrieval（上下文检索）是什么？
**答题要点**
- 传统切块脱离文档上下文（"该指标上升了 5%"不知道指什么）。
- Contextual Retrieval：给每个块**前置一段由 LLM 生成的上下文说明**（这个块在原文中讲什么），再嵌入。检索时更准。
- 常与 **BM25 + 重排**组合，效果提升明显。
**加分点**
- 提「代价是**每个块都要一次 LLM 调用**生成上下文，建库成本上升」。
- 提「是对**切块损失上下文**问题的直接修补」，和"父块/相邻块"思路互补。

## Q9. 什么是 Agentic RAG / Self-RAG？
**答题要点**
- 从"一次性检索→生成"升级为**模型自主决定要不要检索、检索几次、结果够不够**：
  - **Agentic RAG**：把检索当工具，Agent 按需多轮检索、改写查询、判断是否继续。
  - **Self-RAG**：模型用特殊标记**自我反思**——是否需要检索、检索内容是否相关、生成是否被支撑，不达标就重来。
- 价值：复杂/多跳问题效果更好，且**按需省调用**。
**加分点**
- 提「代价是**延迟与不确定性上升**」，要设检索轮次上限。
- 提「与查询路由结合：简单问题直接答，复杂问题才进 Agentic 流程」。

## Q10. 跨语言 / 多语言 RAG 怎么做？
**答题要点**
- 场景：用户用中文问，资料是英文/多语。
- 方案：① **多语 Embedding**（多语言模型把不同语言映射到同空间）；② **查询翻译**（译成资料语言再检索）；③ **统一翻译到中/英**再建库；④ 生成时译回用户语言。
- 难点：术语翻译一致性、语言特有的语义差异。
**加分点**
- 提「**多语 Embedding 通常优于"先翻译再检索"**（少一次失真），但要看模型质量」。
- 提「**评测要分语言做**，别只用英文指标」。

## Q11. Text-to-SQL 与结构化数据 RAG 怎么做？
**答题要点**
- 让模型把自然语言转成 SQL 查结构化库。关键环节：
  - **Schema Linking**：正确关联问题里的词 ↔ 表/列名；
  - **SQL 生成 + 校验**：语法校验、在只读库试跑、限制危险语句（只允许 SELECT）；
  - **自我纠正**：执行报错回喂模型修正。
- 与文本 RAG 互补：结构化问题走 SQL，非结构化走向量检索。
**加分点**
- 提「**给模型看 schema + 少量示例（few-shot）** 大幅提升准确率」。
- 提「**安全**：只读账号、限行数、防 SQL 注入」。
- 提「**查询路由**」决定走 SQL 还是向量检索。

## Q12. RAG 查询意图分类与路由（Query Routing）怎么做？
**答题要点**
- 不是所有问题都走同一条链路：闲聊直接答、结构化问题走 SQL、文档问题走向量检索/GraphRAG、需要实时信息的走搜索。
- 做法：轻量分类器/小模型判断意图 → 路由到对应 pipeline → 各链路结果统一组装。
- 价值：**提质量（用对工具）+ 降成本（别小题大做）**。
**加分点**
- 提「路由错误要有**兜底**（可回落默认链路）」。
- 提「**多意图/混合意图**」的处理（一个问题既问文档又问数据）。
- 提「路由决策也要**可观测+可评测**」。
## Q13. RAG 的拒答与不确定性处理怎么做？（Abstention / "不知道就说不知道"）
**答题要点**
- 核心认识：RAG 最贵的错不是"答得不精确"，而是**检索不到也硬编**——宁可拒答，也不要编。
- 两道闸门：
  - **检索侧**：检索结果够不够？看相似度阈值、rerank（Cross-Encoder）分数阈值，或"命中 chunk 数是否 ≥ 1 且分数达标"；
  - **生成侧**：答案有没有被上下文**支撑**？做 groundedness / 引用覆盖率校验（每条结论必须挂到具体 chunk）。
- 任一闸门不过关 → 走拒答或澄清。拒答分三档：**直接说不知道** → **请用户补充信息 / 澄清** → **转人工 / 转其他链路**。
**加分点**
- 提「**阈值别拍脑袋**」：用标注集画 precision-recall 曲线，按"错答成本 vs 拒答成本"选平衡点。
- 提「**拒答率本身要监控**」：太高像废物、太低像骗子，要作为线上指标跟着 groundedness 一起看。
- 提「**答案级 groundedness 校验**（LLM-as-judge 或 NLI 蕴含判断）比只看检索相似度更准」，并提「**拒答也是一种安全策略**，别被'你随便猜一个'绕过」。
